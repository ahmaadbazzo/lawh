# لَوح (Lawh) — تجربة كتابة فوق الآيات | قيد التطوير

تطبيق Flutter (Material 3) بواجهة مستوحاة من المصحف: زخارف نجمية ذهبية، لافتة لكل سورة، وميداليات لنهاية الآيات.
يكتب المستخدم الآية من حفظه بدون تشكيل، فيطابقها التطبيق كلمة بكلمة (أخضر/أحمر)، ثم يعرضها بالرسم العثماني الكامل برواية **حفص عن عاصم**.
يعمل **أوفلاين بالكامل** ولا يجمع أي بيانات.

## ما الجديد في الإصدار 1.1.0
- هدف يومي قابل للتعديل مع حلقة تقدّم محفوظة محلياً.
- انتقالات RTL ناعمة تحترم إعداد تقليل الحركة في النظام.
- بحث السور يتجاهل التشكيل ويقبل الأرقام العربية والهندية.
- تحسين تطبيع الهمزات وبعض اختلافات الرسم الإملائي.

## المميزات
- القرآن كاملاً (٦٬٢٣٦ آية، ١١٤ سورة) — يُبنى تلقائياً عند كل بناء ويُتحقق منه.
- ثلاثة أنماط: آية بآية، تسميع حر للسورة (مع نتيجة كل آية)، اختبار حسب النطاق.
- مستويات مساعدة، سجل أخطاء، إحصائيات وتتابع يومي، وضع داكن، تحكم بحجم الخط.

## كيف تنشئ الريبو وتبني التطبيق (بدون تثبيت Flutter)
1. في GitHub: **New repository** → اسمه `lawh` → اجعله **Private** (مهم لاحقاً للتوقيع).
2. فك ضغط الـ zip، ثم من الريبو: **Add file → Upload files** واسحب **كل المحتويات** (بما فيها مجلد `.github`).
   - على Mac اضغط `Cmd+Shift+.` لإظهار الملفات المخفية. أو أنشئ الملف يدوياً: **Add file → Create new file** واكتب `.github/workflows/build.yml` والصق محتواه.
3. افتح تبويب **Actions** ← **Build Lawh** ← **Run workflow**.
4. بعد نحو ٦–١٠ دقائق، من صفحة التشغيل نزّل **Lawh-APK** (للتجربة على جوالك) و**Lawh-AAB** (لمتجر Google Play).

> إذا فشل البناء: افتح الخطوة الحمراء وانسخ آخر ٤٠ سطراً.

## التجهيز للنشر
### ١) مفتاح التوقيع (مرة واحدة)
1. Actions ← **Generate upload keystore (run once)** ← Run workflow.
2. نزّل الـ artifact `upload-keystore` واحفظ الملفين في مكان آمن (فقدان المفتاح يعني صعوبة تحديث التطبيق).
3. Settings ← Secrets and variables ← Actions ← أضف أربعة أسرار بالقيم الموجودة في `credentials.txt`:
   `KEYSTORE_BASE64` و`KEYSTORE_PASSWORD` و`KEY_ALIAS` و`KEY_PASSWORD`.
4. شغّل **Build Lawh** من جديد: سيُوقَّع الـ AAB/APK تلقائياً.

### ٢) هوية التطبيق
- معرّف الحزمة في `build.yml` (`APP_ORG` ← الناتج `com.bazzo.lawh`). غيّره **قبل** أول نشر؛ لا يمكن تغييره بعده.
- رقم الإصدار: `version:` في `pubspec.yaml` (الجزء بعد `+` يُستبدل برقم التشغيل تلقائياً).

### ٣) المتجر
- نصوص جاهزة بالعربية والإنجليزية في `store/`.
- سياسة الخصوصية في `docs/PRIVACY.md` (انشرها على رابط عام مثل GitHub Pages في ريبو عام منفصل).
- تحقق من شروط Google Play لبلدك ولحسابات المطورين الجدد (قد يُطلب اختبار مغلق قبل النشر). وإن لم يناسبك: وزّع الـ APK مباشرة عبر **GitHub Releases** أو متاجر بديلة.

## هيكل المشروع
```
lib/            الكود (screens, providers, services, widgets/ornaments.dart للزخارف)
assets/         بيانات السور، الخطوط، الأيقونة
scripts/        build_quran_data.py (القرآن الكامل) • fetch_fonts.py • configure_android.py
.github/workflows/   build.yml • generate-keystore.yml
store/ docs/    نصوص المتجر وسياسة الخصوصية
```
مجلد `android/` يُولَّد في كل بناء ولذلك غير موجود في الريبو.
